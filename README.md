# turn_based_nba_card_game

2017 骑勇总决赛的 **1v1 斗将式回合制卡牌对战**：三国杀的回合骨架 + 博德之门的 d20 判定 + 真实 NBA 战术相克。

> **明确不是什么**：不是真实命中率模拟器，不是构筑类卡牌（唯一构筑环节是选教练）。

---

## 马上试玩

**方式一：直接打开**

双击 `game.html` —— 单文件、零依赖、零后端，`file://` 下可直接运行。

**方式二：本地跑**

```bash
node build.mjs     # 从 rules.mjs + game.template.html 生成 game.html
```

**方式三：分屏对战**

两个浏览器窗口分别打开：

```
game.html?side=CLE      # 骑士视角
game.html?side=GSW      # 勇士视角
```

无 `?side=` 的窗口会显示"加入"界面。两窗口通过 `BroadcastChannel` 同步，`file://` 下实测可通，无需起服务器。

## 玩法速览

**核心循环**

```
双方同时秘密选人 → 同时翻牌
     ↓
进攻方：打战术牌，或直接出进攻牌跳过战术
     ↓
防守方应对（沉退 / 换防 / 包夹 / 延误 …），也可「原始对位」不出牌
     ↓
进攻方选定出手方式 → 防守方决定是否花干扰牌
     ↓
d20 判定（自动掷）→ 结果 → 交换球权
```

**关键规则**

- 每回合：进攻方摸 1 进攻牌 + 1 战术牌，防守方摸 1 防守牌 + 1 战术牌
- 手牌上限 11，起手 8（3 攻 / 3 防 / 2 战）
- 一回合最多得一球；不中时 TT 可拼前场篮板换一次重试
- 先得 **15 分**获胜；牌堆见底则分高者胜
- 盲选保密：对手整排 5 张全部翻面，只盖被选中的那张等于把答案写在脸上

**防守牌的四种用途**（这是设计上刻意区分的，不是数值大小的差别）

| 牌 | 效果 | 定位 |
|---|---|---|
| 干扰投篮 | 三分/中投 +4，对突破篮下几乎无效 | 克跳投 |
| 封盖 | 扣篮/空接 +5，对外线基本无效 | 克内线 |
| 抢断 | 掷 d20 ≥ 15 直接断球（约 30%） | 赌断球 |
| 紧逼 | 各类 +2，额外消耗对手 1 点体能 | 耗体能 |

## 项目结构

| 文件 | 作用 |
|---|---|
| `rules.mjs` | **规则内核，唯一真相源**。属性、牌表、相克矩阵、DC 计算、体能曲线 |
| `sim.mjs` | 校准模拟器，双方启发式 AI 对打 |
| `game.template.html` | 界面模板，含 `/*__RULES__*/` 注入点 |
| `build.mjs` | 把 `rules.mjs` 内联进模板 → `game.html` |
| `uitest.mjs` | 真实 Chrome 交互测试，91 项断言 + 截图 |
| `playtest.mjs` | **自动对局机器人**，纯 DOM 点击打完整局，卡死即失败 |
| `run.mjs` | 一键跑全流程 |
| `game.html` | 可玩产物 |
| `DESIGN.md` | 设计文档（含每次调参的实测依据） |

**规则只写在 `rules.mjs` 一处**，模拟器与界面都从它读。`build.mjs` 构建时会校验这一点。

## 数值校准

4000 局蒙特卡洛 + 8 局真实浏览器对局：

| 指标 | 值 | 目标 |
|---|---|---|
| 得分回合占比 | 65.7% | 65-78% |
| 每回合得分 | 1.56 | 1.4-1.9 |
| 一局回合数 | 17（12-23） | 14-30 |
| 用到球员数 | 4.97 / 5 | ≥3.5 |
| 胜率 | CLE 49.9% / GSW 50.1% | 接近 50/50 |
| 命中率区间 | 45% - 90% | 有防守时 50-70% |
| 无人可派 | 0.00% | 0% |

> 命中率刻意**高于**真实 NBA（真实每回合约 1.10 分）。这是卡牌游戏不是模拟器：大多数局面双方都有对策牌，进攻效率太低会让出牌决策失去意义。

## 开发与验证

```bash
node run.mjs           # 全流程：sim → build → test → play
node run.mjs sim       # 只跑 4000 局校准
node run.mjs build     # 只构建
node run.mjs test      # 只跑浏览器断言
node run.mjs play      # 只跑自动对局机器人
```

**四步必须全绿才能交付。** 特别是 `play`（自动对局机器人）—— 它完全通过真实 DOM 点击打完整局，任何一步找不到可点击项就报卡死。

这一步是血泪教训：早期版本 88 项断言全绿，但玩家实际操作两步就卡死。断言测试只走脚本设计好的那条路径，**走不到玩家真实操作序列的角落**。

浏览器测试需要 puppeteer，它装在 `../nba2k-player-ratings/`，`run.mjs` 负责搬运与清理。

## 技术笔记

- **零后端分屏**：`BroadcastChannel` 同步，双窗口共享 `localStorage` 状态
- **确定性随机**：`mulberry32`，种子来自 `S.seed` 与递增的 `rollSeq`，保证可复现
- **规则注入**：`build.mjs` 把 `rules.mjs` 内联进 HTML，产物自包含
- **调试桥**：页面暴露 `window.__S / __MY / __dispatch / __calcDC / __setView`，用于构造任意局面与逐项拆解数值

详细的调参依据与踩坑记录见 `DESIGN.md`。
